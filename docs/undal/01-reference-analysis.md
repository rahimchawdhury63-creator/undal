# 01 — Reference-image analysis and Undal design interpretation

## Review basis and limits

All **130 supplied image files** were visually reviewed using readable, labelled review sheets; landscape web images were also reviewed in larger panels. Originals remain unchanged. The [inventory](reference-inventory.tsv) records every ID, exact path, dimensions, and SHA-256 hash. Counts: customer app 41; customer web 24; partner folder 53; rider folder 12. There are 124 unique image contents because six partner-folder files exactly duplicate rider-folder files.

The five `.txt` marker files are empty/whitespace-only: the root folder marker and one marker in each app folder. They contribute no hidden specification. C09 has a black content area; no login/payment/security behavior can be inferred from it. Several smaller images are promotional store-listing artwork, not captured operational states. Their marketing claims are not evidence of implemented backend behavior.

Personal names, addresses, email addresses, phone numbers, account identifiers, order IDs, competitor logos, mascots, and food photography in references must not become Undal production assets, seed data, or documentation examples. Preserve reference provenance without copying personal data into new content.

**Interpretation key:** adopt = the generic interaction is in scope; adapt = retain the useful pattern with Undal's policy/design; exclude = the business feature conflicts with scope; unknown = insufficient visible evidence. Backend requirements below are Undal design decisions, not claims about competitors' internal systems.

## E. Cross-reference design synthesis

### Customer: discovery → decision → checkout → fulfillment

Persistent address context and search should anchor the experience. Use a short food-only service taxonomy, readable cuisine navigation, organic vendor cards with ETA/fees/rating/favorite, a coherent vendor/menu page, a modifier sheet, an always-understandable cart, and a COD checkout with one final authoritative total. Keep order progress and support reachable without promotional obstruction. An active order gets priority over marketing banners and connection-hungry browsing widgets.

### Partner: attention → accept → prepare → handover → reconcile

Top-level navigation should prioritize Live Orders, Overview, Menu, Earnings, and More. Live queue states must distinguish new, accepted/preparing, ready, completed, disconnected, closed by schedule, manually paused, and device-unreachable. An alert acknowledgement is not order acceptance. Preparation controls must be large and fast, with a recommended value, plus/minus, explicit confirmation, upper bound, and an audited change event. Handover displays a protected QR and order summary; payouts show exactly where every deduction came from.

### Rider: readiness → offer → route → handover → delivery → cash

Use a map/task-sheet combination with a usable list-only fallback. Make earnings, distance, pickup count, expected route time, COD collection, and batch commitment visible before acceptance, without exposing unrelated customer PII. Provide large safe actions, explicit QR scanning/handover, cash confirmation and incident/support routes. Online state, GPS freshness, notification readiness, and cash restrictions must remain visible. Do not encourage interaction while moving or lock access to safety/support.

### Web and admin responsiveness

Use mobile-first web reflow: vendor grids become single-column cards; menu/cart sidebar becomes a sticky cart action plus sheet; filter sidebars become accessible drawers; operational tables gain meaningful row/card layouts rather than shrinking text. Desktop density must not leak into a 200px fallback. Test browser chrome/keyboard/safe areas separately from app UI; screenshot-capture toolbars are not product elements.

### Original Undal visual direction

Proposed direction: warm food-led neutrals, deep green structural surfaces, a restrained energetic orange accent, strong contrast, rounded but not toy-like cards, consistent iconography, and locally appropriate English/Bangla typography. Colors and component tokens are proposals, not contrast-tested facts. Validate every text/action combination to WCAG AA before adoption. Use original commissioned/owned brand assets and vendor-authorized food images, not competitor mascots, logos, screenshots, or borrowed food photos.

### What the references do not establish

No image proves an internal dispatch algorithm, unlimited free capacity, statutory tax interpretation, FCM force-stop behavior, payout correctness, KYC compliance, 2,000 features, or error-free operation. New Undal workflows—identity review, secure QR redemption, financial approvals, remittance review, quota admission, recovery alarms, and many admin operations—need explicit requirements, state machines and tests rather than visual guesswork.
