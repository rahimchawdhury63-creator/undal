# Decision record

[`35 §7`](../35-execution-plan.md) leaves 31 points to the building agent. The TiDB migration closed
two of them outright (the `gen_random_uuid` source, the PostGIS index parameters), leaving **29
open**; this record adds **three** that the corpus leaves implicit but the build cannot avoid
(D31–D33) and **two visible deviations** from the corpus that the operator's brief forces
(D34–D35). Every entry states the decision, what was rejected, and why — so a later reader can tell
a choice from an accident.

Format: **Decision.** *Rejected:* … *Why:* …

---

## Android (D1–D9)

**D1 — Navigation.** Navigation Compose 2.8 with **type-safe serializable routes**; each feature
module owns its `nav/` graph and the app module composes them. *Rejected:* string routes, Voyager,
Decompose, a hand-rolled navigator. *Why:* type-safe arguments make the 14 deep-link paths
compile-checked, the library is first-party, and nav graphs are testable without a UI harness.

**D2 — State model.** Plain `ViewModel` + `StateFlow` + a sealed intent type with a pure reducer;
no Molecule. *Rejected:* Molecule, MVI frameworks. *Why:* every screen's logic must be unit-testable
on the JVM without Compose; a pure reducer gives that for free, and a 283-screen app does not need a
second concurrency model.

**D3 — Room → domain mapping.** Explicit mapper functions in `core/database/mapper/`, one per
entity. *Rejected:* annotation processors, auto-mappers, mapping in the repository. *Why:* money
and nullability mistakes hide inside generated mapping code; an explicit map is greppable, diffable
and 100%-coverable.

**D4 — Icon pipeline.** `design/icons/*.svg` → a committed generator (`scripts/design/vectors.ts`,
run in CI, output diffed) → `core/designsystem/icons/*.kt` as `ImageVector`. *Rejected:* runtime SVG
parsing (a library and a frame-time cost), hand-porting 118 icons. *Why:* compile-time vectors, no
runtime dependency, and a regeneration diff in CI makes drift impossible.

**D5 — Image cache.** Coil 3 with a 250 MB / 60-day LRU on customer and partner, 120 MB on rider,
cache keys including the chosen variant, and map tiles in MapLibre's own cache so they cannot be
evicted by menu photography. *Rejected:* one shared cache, unbounded cache. *Why:* the rider's
14 MB-per-shift budget (`19 §9`) depends on tiles surviving a shift.

**D6 — Rider offline map.** MapLibre Native with pre-cached vector tiles for the rider's zone.
*Rejected:* Leaflet in a WebView (battery, gesture latency, a second rendering engine, no
`no-layout-animation` guarantee). *Why:* one engine, one style, one attribution component shared with
the admin map; turn-by-turn still hands off to Google Maps (`19 §5.1`).

**D7 — Cronet.** `com.vk.knet:okcronet`, pinned in `libs.versions.toml`; vendoring only via a Gradle
source dependency if an API is missing. *Rejected:* building Cronet from source in Actions (minutes
budget), plain OkHttp (loses HTTP/3, criterion A8). *Why:* the brief names Okronet, and a pinned
published artifact is reproducible.

**D8 — Baseline profiles.** Generated by `android-test.yml` on a controlled emulator with
`BaselineProfileRule`, committed as `src/main/baseline-prof.txt`, regenerated on every release tag.
*Rejected:* hand-written rules, generating on every PR (cost, noise). *Why:* cold start ≤ 1 400 ms
is build-failing, and profiles are the cheapest way to hold it.

**D9 — DI in tests.** Hilt in production; `core:testing` exposes hand-written fakes and
`@TestInstallIn` replacements, and unit tests construct objects directly. *Rejected:* running the
Hilt test runtime for 8 000 JVM tests. *Why:* Robolectric + JUnit5 want plain constructors; the Hilt
test graph costs seconds per class for no coverage gain.

## Workers (D10–D16)

**D10 — Middleware order.** `request-id → logging → security-headers → body-limit → auth → rbac →
step-up → idempotency → rate-limit → zone-scope → handler`, with the envelope written last on both
paths. *Rejected:* idempotency before auth, rate-limit before auth. *Why:* the idempotency key is
scoped to an actor, and rate limits must be per-actor where an actor exists, falling back to IP.

**D11 — Database connection.** `@tidbcloud/serverless` over HTTP, no pool, one lazily created client
per isolate. `DATETIME(6)` columns mean no time-zone conversion happens on write, so the invariant is
enforced three ways: every business timestamp is **app-generated UTC**, `CURRENT_TIMESTAMP(6)` is
used only as a default on audit rows, and a boot probe asserts `@@session.time_zone = '+00:00'` and
fails the isolate if it is not. *Rejected:* relying on a connection-string parameter alone,
`TIMESTAMP` columns, a pooled driver. *Why:* the corpus's UTC guarantee must not depend on a
variable a future driver version might silently change.

**D12 — Python runtime.** Pyodide on the Workers Python runtime. *Rejected:* RustPython/WASM
(incomplete stdlib, no numerics), a second JS implementation from day one. *Why:* the engines are
pure arithmetic and statistics; if cold start exceeds 400 ms the fare engine is ported to TypeScript
(R37) with the differential test guaranteeing identical results.

**D13 — Feature-store hot tier.** KV for versioned config, weights and `vendor_stats` snapshots;
Cache API only as an in-isolate memo of a feature payload for a single request. *Rejected:* Cache API
for config, D1 for features. *Why:* KV's 1 000 writes/day fits config that changes rarely, its
100 000 reads/day fits the hot path, and a per-request memo needs no durability.

**D14 — SSE keepalive.** A `: ping` comment frame every 15 s for proxy/idle keepalive, plus a real
`tick` event every 15 s carrying server time **only** on streams that compute staleness (order
tracking, admin map — `22 §4`). *Rejected:* an `event: heartbeat` on every stream. *Why:* comments
never reach an `EventSource` listener, so they cost nothing; ticks are required where staleness is
displayed and would be noise everywhere else.

**D15 — Binding errors.** Service bindings return the same envelope shape rather than throwing;
`undal-core` maps a downstream failure to `502` with `UPSTREAM_{SERVICE}_FAILED`, preserves the
request id, and writes a dead letter. *Rejected:* letting exceptions cross the boundary. *Why:* a
thrown binding error loses the error code and the correlation id, which is exactly what an incident
review needs.

**D16 — Retry budget.** One request budget (2 500 ms) threaded through hops as `budget_remaining_ms`;
each nested call receives `min(remaining / 2, its own budget)`; retries only on idempotent verbs and
`1213`/`1205`/`5xx`; at most 2 retries per hop and 4 across the chain. *Rejected:* per-hop retry
budgets. *Why:* nested retries multiply tail latency; a single budget makes the p99 provable.

## Web (D17–D22)

**D17 — Router.** React Router 7 in **data mode** (`createBrowserRouter` + loaders). *Rejected:*
framework mode, Next.js, client-only rendering. *Why:* loaders give the pre-render pipeline
data-before-render, while Vite stays in control of the build that Pages deploys.

**D18 — Pre-render.** Our own plugin in `web/storefront/prerender/` (route manifest from
`/v1/public/sitemap-data`, HTML emission, JSON-LD, thin-page failure). *Rejected:* `vite-plugin-ssg`,
a Gatsby-style framework. *Why:* `prerender-verify` requires per-route content assertions a generic
plugin cannot express, and Bengali mirrors double every route.

**D19 — Styling.** CSS Modules + custom properties generated from `design/tokens.json`.
*Rejected:* vanilla-extract, Tailwind, CSS-in-JS. *Why:* zero runtime, static CSS that survives
pre-rendering, and a critical-CSS budget of 42 KB that extraction can actually meet.

**D20 — Virtualisation.** `@tanstack/react-virtual` for admin grids and any list over 60 rows.
*Rejected:* react-window (older API), no virtualisation. *Why:* it composes with TanStack Table,
which the 60+ grids already need, and it is headless.

**D21 — Charts.** Recharts in the admin; hand-rolled SVG in the storefront and apps.
*Rejected:* Recharts everywhere. *Why:* the storefront's 160 KB bundle budget cannot carry a charting
library for three visuals; the admin's budget (420 KB) can.

**D22 — Service worker.** Hand-rolled (~150 lines) implementing the five strategies in
`20 §7` explicitly. *Rejected:* Workbox. *Why:* Workbox adds weight and its defaults are broader than
the corpus's narrow scope — "API mutations are never cached" must be a line of code, not a config
option.

## Data (D23–D26)

**D23 — UUIDv7.** One implementation per language — `packages/contracts/src/common/ids.ts`,
`workers/brain/src/lib/ids.py`, `android/core/common/Uuid.kt` — 48-bit millisecond timestamp + a
12-bit intra-millisecond counter + 62 random bits, against one shared test vector and a 10 000-call
monotonicity test per language. SQL never generates an id. *Rejected:* a SQL function (impossible
without stored functions), v4, `AUTO_INCREMENT`. *Why:* ids must sort by creation time for index
locality, and TiDB has no `gen_random_uuid()` at all.

**D24 — Item snapshots.** Full snapshot JSON on `order_items` (names en/bn, unit price, option labels
and deltas, photo URL), not a delta. *Rejected:* delta against the live menu. *Why:* an invoice must
be reproducible years later, and a delta against a mutable menu cannot be; `receipt-reproducibility`
(A76) is the test.

**D25 — Trace retention.** No partitioning for `brain_traces`; TiDB TTL by age (7 days default, 90
for dispatch and money-adjacent engines) plus the request-triggered sweep as a fallback.
*Rejected:* monthly partition tables, unlimited retention. *Why:* Starter has TTL, the 5 GiB ceiling
is the tightest constraint in the platform, and partitioning would split the single replay query.

**D26 — `vendor_stats`.** Maintained by an upsert inside the order-delivered write path, with a
nightly integrity job recomputing a sample and comparing. *Rejected:* a refresh-on-read materialised
view. *Why:* the ranking hot path must not pay an aggregate join; a bounded upsert on the write path
costs one statement.

## Process (D27–D30)

**D27 — Task graph.** Turborepo with `codegen → build → typecheck → lint → test`, explicit `inputs`
and `outputs`; remote cache off. *Rejected:* remote caching (a paid service for a 40-second cache
hit), Nx. *Why:* the free-tier rule outranks a build-speed win.

**D28 — Versioning.** No changeset tool. Versions live in four constants (`versionName` per app, a
Worker version, a contract version) bumped in the release commit, and `lockfile-drift` guards the
lockfiles. *Rejected:* Changesets, semantic-release. *Why:* nothing here is published to a registry;
a second source of truth for versions is pure overhead.

**D29 — Screenshot tolerance.** Pixel diff only for the 1 200 deliberate visual snapshots
(0.1% differing pixels, per-pixel threshold 0.1). The responsive matrix asserts **layout
invariants** — no overflow, no clipping, target sizes — rather than pixel equality.
*Rejected:* pixel-diffing 56 600 renders. *Why:* cross-platform font rasterisation makes pixel
equality of an unrendered state meaningless; the invariant is the real contract (`A151`, `A154`).

**D30 — Flaky tests.** A failing-on-rerun test moves to a `quarantine` suite that **still runs and
must still pass** but does not gate merges, with an auto-created issue and a 7-day expiry that turns
the build red when it lapses. *Rejected:* skipping, deleting, "fix later". *Why:* the corpus's zero
tolerance needs a mechanism that cannot be quietly ignored; an expiring quarantine is that mechanism.

## Implicit, and decided here (D31–D33)

**D31 — Generated Kotlin models.** `scripts/codegen/kotlin-models.ts` generates `@Serializable` data
classes for all 412 endpoints into `core:network/model/generated/`, with money as `Paisa` (a `Long`
value class) and never `Double`. *Rejected:* hand-written DTOs. *Why:* 412 hand-written mirrors of a
Zod contract drift within a week, and a generated `Double` is a money bug waiting for a fare.

**D32 — QR key rotation.** Two HMAC keys are accepted for a 24-hour overlap
(`QR_HMAC_KEY`, `QR_HMAC_KEY_PREVIOUS`), and `rotate-secret.yml` writes both. *Rejected:* a single
key (rotation invalidates in-flight pickups). *Why:* `27 §6.1` requires rotation without invalidating
in-flight orders; two keys is the only way to satisfy it.

**D33 — Error text ownership.** Every error code's English and Bengali copy lives in
`packages/contracts/src/errors/registry.ts` and is extracted into `packages/i18n`; the server returns
a code plus an optional server-rendered sentence, and clients render from the catalogue.
*Rejected:* server-only strings, client-only strings. *Why:* `i18n-completeness` must be able to
prove all 184 codes exist in both locales, and offline clients must still be able to explain a
failure they received earlier.

## Visible deviations from the corpus (D34–D35)

**D34 — One Pages project, not two.** The storefront and the admin SPA deploy as one project: `/`
serves the pre-rendered storefront, `/admin/*` serves the admin SPA with a **path-scoped** CSP in
`public/_headers` (stricter: no `img-src data:`, no inline styles), an `HttpOnly` refresh cookie
scoped to `/admin`, and a Cloudflare Access policy on `/admin/*`. [`21 §13`](../21-admin-panel.md)
specifies a separate project at `admin.{domain}`; the operator's brief specifies **one Pages
project**, and this is the closest thing to both. *Rejected:* two projects (violates the brief),
one project with one shared CSP (loses the admin's stricter policy). *Why recorded here:* the
residual risk is an origin shared by a public storefront and the admin surface — R36 in the build
plan — and it should be a decision someone can find, not a surprise.

**D35 — `minSdk 26`, not 24.** Non-negotiable 39 in [`01`](../01-mission-and-non-negotiables.md)
requires Android 8.0 and names its own test matrix (API 26/30/34/35); [`16 §3.1`](../16-android-foundation.md)
and [`18 §1`](../18-partner-app.md) say 24. The non-negotiable wins because it is explicitly ranked
above the documents and because CI can only promise what it tests. *Rejected:* 24 (untested floor, a
stated rule broken), 23 (below 16's own warning). *Why recorded here:* it excludes Android 7.x
devices — a small, shrinking share of the Bangladeshi base — and that cost should be visible rather
than discovered in a Play Console device report.

## D36 — The five platform-wide error codes keep their bare names

**Decision.** The sixteenth group file is `packages/contracts/src/errors/rows/system.ts`, but its
five codes are exactly `INTERNAL`, `SERVICE_DEGRADED`, `DEPENDENCY_TIMEOUT`, `IDEMPOTENCY_CONFLICT`
and `NOT_IMPLEMENTED` — no `SYSTEM_` prefix — and the three `OAUTH_*` codes are counted inside the
`AUTH_` group.

**Rejected.** Inventing `SYSTEM_INTERNAL` and the rest so that every prefix matches its table row.

**Why.** `08 §11` labels the row `SYSTEM_` but names the codes without it, and clients match on the
code string exactly. The registry is the contract, so the 184 strings are authoritative and the table
label is the typo. The parity test asserts `AUTH_ + OAUTH_ = 21` and `BARE = 5` so the reconciliation
lives in the test rather than in a reader's head.

## D37 — `platform_config.zone_id` uses the all-zero UUID for "global"

**Decision.** `zone_id BINARY(16) NOT NULL DEFAULT 0x00…00`, where the zero UUID means the global
default. The DDL in `29` was rewritten from CockroachDB types to `VARCHAR`/`BINARY(16)`/`JSON`/
`DATETIME(6)`.

**Rejected.** Keeping `zone_id UUID NULL` with a nullable primary-key column.

**Why.** MySQL — and therefore TiDB — will not store `NULL` in a primary-key column: the insert fails
with 1048 rather than creating the global row the design describes. The sentinel keeps the same
semantics, the same key order and the same access path, and it is visible in the type instead of in
a comment that the database ignores. `no-postgres-dialect` caught the original DDL on the first
guardrail run.

## D38 — An unknown route answers `NOT_IMPLEMENTED`, not `404`

**Decision.** `undal-core` and `undal-realtime` return HTTP 501 with code `NOT_IMPLEMENTED` and
`details: { method, path }` for any path they do not serve.

**Rejected.** Adding a `ROUTE_NOT_FOUND` code (which would break the 184-code contract) or borrowing
`CATALOG_VENDOR_NOT_FOUND` (which would lie about what was missing).

**Why.** On a versioned API an unknown path means "this build does not serve this", which is exactly
what 501 says in RFC 9110, and it is the one registered code whose meaning is true. A `404` would tell
the client the resource exists elsewhere and send it looking.

## D39 — Guardrail exemptions are named, not silent

**Decision.** Three exemptions are written into the rules themselves: markdown is exempt from the
700-line cap; test and fixture paths are exempt from the placeholder scan and the money-float scan;
`scripts/guardrails/` is exempt from the placeholder scan.

**Rejected.** Keep-whole rules with a suppression comment, or a `# guardrail-ignore` escape hatch.

**Why.** A rule that can be silenced locally stops being a rule. Each exemption below is a property of
the tree rather than of a file: the spec corpus is one document per subject and splitting
`06-data-model-tidb.md` at line 700 would separate a table from the paragraph that explains it; tests
are not shipped and a test that asserts "no TODO in the registry" must be able to spell the word; the
guardrail tooling is the code that lists the forbidden words.

## D40 — The Kotlin differential runs on its own workflow

**Decision.** `ci.yml` compares TypeScript against Python on every push; `money-math.yml` adds the
Kotlin answers from the JVM-only `:shared:money` module.

**Rejected.** Setting up a JVM in the main gate for one more language.

**Why.** Three minutes on every push for an assertion whose inputs change only when
`packages/money` or `android/shared/money` change is three minutes the maintainer spends waiting on a
tablet. The paths filter on `money-math.yml` runs it exactly when it can fail.

## D41 — Operational workflows ship before the scripts they call

**Decision.** `migrate`, `verify-schema`, `d1-migrate`, `db-query`, `housekeeping` and `brain-replay`
exist from this response as the interface a browser-only maintainer uses, while the scripts they
invoke arrive with the migration pipeline (R6) and the Brain (R17).

**Rejected.** Deferring the workflows until their scripts exist.

**Why.** Each of these is a `workflow_dispatch` button, and a button that exists, is documented and
fails loudly at a named missing script is better than a button discovered missing at 2 a.m. with a
broken deployment — the failure names its own remedy. Nothing here runs on push, so the gate that
guards every commit is unaffected, and no step in any of them pretends to have done work it did not do.
